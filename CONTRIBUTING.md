# Contribuir

## Idioma

La documentación se redactará en español. Los identificadores exigidos por especificaciones externas pueden mantenerse en inglés.

## Flujo de trabajo

1. Crear una rama desde `main`.
2. Modificar la guía, referencia, skill o plantilla correspondiente.
3. Justificar el cambio y citar fuentes oficiales.
4. Comprobar enlaces, Markdown y encabezados YAML.
5. Abrir un pull request para revisión.

## Requisitos del pull request

El título y la descripción del pull request deben estar en inglés y Markdown. La descripción debe incluir:

- problema observado;
- solución propuesta;
- formatos afectados;
- impacto en accesibilidad;
- fuentes utilizadas;
- capturas o ejemplos cuando sean necesarios;
- compatibilidad con plantillas existentes.

## Criterios de aceptación

- No contradice normativa ni identidad oficial.
- Diferencia claramente requisitos y recomendaciones.
- Incluye criterios verificables.
- No incorpora activos institucionales obtenidos de fuentes no oficiales.
- Mantiene coherencia con el `DESIGN.md` raíz.
- Actualiza las referencias o plantillas afectadas.

## Cambios en colores y logotipos

Los cambios en colores institucionales, firmas, símbolos, proporciones o áreas de respeto requieren una referencia oficial verificable. No se aceptarán aproximaciones visuales.

## Versionado

Mientras las guías estén en borrador se usará `status: draft`. Un cambio que altere de forma incompatible tokens, jerarquías o reglas debe incrementar la versión del `DESIGN.md` afectado y explicar la migración.
